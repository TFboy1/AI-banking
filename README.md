# 有数 · 极简 AI Banking

一个聊天页面，加上可收起的历史会话列表和模拟银行面板。六类能力由同一个 Agent 调用银行工具完成：转账、账单分析、理财申赎、卡片管理、订阅管理和跨场景任务。

## 当前版本（2026-10-21 更新）

包含多用户账号隔离、联系人与资金分类、卡账户双向划转、三级交易验证、可选人脸、语音输入、理财和独立证券、外卖和旅行演示平台、定时交易、显式DAG、中断恢复、人工客服、审计与日报图表。

## 启动

环境要求：Windows PowerShell、uv、Node.js 22.12+。后端使用 Python 3.11。

```powershell
# 在项目根目录运行：安装依赖、构建前端、启动后端并托管构建产物
.\scripts\start.ps1

# 已经安装和构建时，可以跳过前端构建
.\scripts\start.ps1 -SkipBuild
```

打开 **http://127.0.0.1:8000**。停止服务使用 Ctrl+C。前端和 API 由同一服务提供，不必另外启动前端开发服务器。

`uv` 复用全局缓存，安装优先使用 hardlink；Windows 上缓存与项目跨盘时会自动退回复制。源码、配置、文档均使用 UTF-8。

### 配置真实大模型

启动脚本会在 `.env` 不存在时从 `.env.example` 复制。填写下列内容，然后重启后端：

```dotenv
LLM_BASE_URL=https://你的兼容接口地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=你的模型名
```

`LLM_BASE_URL` 保留服务商要求的版本前缀，不要带 `/chat/completions`。接口须支持 OpenAI 兼容的 Chat Completions。密钥只读入后端，不返回前端。

`LLM_TOOL_MODE=auto` 默认先使用原生 `tools/tool_calls`。如果模型在尚未调用银行工具时只返回文字，后端会让同一模型输出 JSON 工具计划，再经过原有工具白名单、参数验证和确认流程。没有查询证据的第一段文字不会直接展示。对原生工具调用不稳定、支持 `response_format: json_object` 的接口，可设置 `LLM_TOOL_MODE=structured` 直接走此协议；原生工具支持完整的服务可设置 `native`。结构化响应无效或缺少查询依据时明确报错，不能据此更改银行数据。

没有配置模型时，页面会明确显示“未配置”。你仍可打开模拟银行面板查看数据、查询账单或重置沙箱；聊天不会伪造 AI 响应或交易成功。设置中的“已配置”仅表示配置齐全，网络连通在实际请求时检查。

### 资金计划演示

1. 在“模拟银行”中点击“载入缺口演示场景”。业务日期会固定为 2026-09-30，日常账户余额按房租、生活费与当前有效订阅计算并全部预留；默认 6 个订阅时为 6379 元。
2. 在聊天中发送“我想买台 6000 元的电脑，下个月至少留 3000 元生活费”。助手会从历史流水推断工资和房租，展示当前执行与工资到账后执行两种方案。
3. 在方案卡点击“挑战工资延期”或“测试突发支出”。挑战只做单因素精确搜索，并标明范围；修复建议会生成新的计划版本并重新验证。
   方案卡可切换执行时点，查看逐事件的可自由安排余额曲线、首次资金缺口及计算依据。
4. 采用可行方案后，资金预留开始生效；实际消费或转存仍需单独确认。工资尚未实际到账时，不会提前生成依赖工资的扣款确认。
5. 登记“工资到账时提醒”，再从模拟银行触发工资到账。系统只入账一次，按最新账务生成待采纳建议；用户采纳后才出现转存确认卡。

计划、承诺与成功交易回执持久化并跨会话共享。另一会话尝试使用已安排资金时，确认阶段会重新检查并阻止冲突；查询 `list_plans` 可看到承诺来源、期限及储蓄目标实际完成额。

账单、资金方案与确认卡可展开“为什么这样建议”，查看银行记录、检查项与结论。转账和申购诊断只读取当前状态，一次列出已知阻碍；卡片上的下一步按钮只填入聊天草稿，不会自动发送或执行。模型上下文中的已知联系人手机号会替换为联系人编号，查询结果只展示脱敏手机号。

### 会话管理

- 点击顶部“新会话”或会话列表中的“新建会话”，开始一段独立对话。
- 顶部的会话图标可展开历史列表，支持切换、重命名和删除。第一条消息会自动成为会话标题，刷新和重启保留记录。
- 各会话的模型上下文、消息和待确认操作独立；余额、持仓、卡片和交易流水属于同一个演示身份，当前账号的各会话共用。
- 切换或新建会话不会取消原会话的待确认操作，可返回原会话继续确认。删除会话会取消尚未确认的操作；已完成的银行交易及审计回执保留。仍在处理请求的会话需等待结束后才能删除。
- “重置演示数据”会清空所有会话并重置整个银行沙箱。服务启动会自动迁移旧数据库，保留已有聊天与资金数据。

## 业务与执行约定

- 金额以整数“分”存储；工具金额参数使用元的字符串。余额、流水、持仓与操作回执由后端事务更新。
- 确认卡片保存已解析的收款人、金额等参数，15 分钟有效。确认时重新检查余额、日限额、卡片状态及产品风险。同一确认重复提交只会执行一次。
- 风险问卷根据用户三项回答生成 R1–R4 演示等级；申购必须匹配等级。初始未测评，赎回不受新增风险测评限制。
- 理财采用固定模拟净值、即时结算；份额保留 4 位。不足一分的申购款向上取整，赎回款向下取整，不计额外手续费。该规则用于本地沙箱，不表示真实产品条款。
- 冻结银行卡后，关联账户的转账和申购会被阻止；解冻后恢复。日限额只统计本次演示产生的支付，种子历史流水不占本次支付额度。
- 本人账户互转及理财本金进出不计入消费统计；异常提示保留交易依据，是待核对线索。
- 订阅识别基于跨月扣费记录并核对协议。取消会关闭模拟代扣协议及后续扣费日期，不退款。首版不连接真实商户，也不运行真实续费扣款。
- 对话、任务、待确认操作和回执均持久化。重启保留待确认卡片；处理中被中断的任务明确标记失败，已确认的操作不会自动重放。
- 每个会话同时接受一条处理中请求，多个会话的任务由后端队列依次处理。每个登录账号的数据独立保存，浏览器使用 HttpOnly 连接 Cookie；应用默认监听 `127.0.0.1`。
- 展示的是简短回复、银行数据及回执，不展示模型内部推理内容。未授权工具、额外伪造参数及绕过确认的变更请求会被拒绝。

## 可扩展业务框架

工具的参数、权限和业务领域由统一能力注册表管理；模型根据当前请求与同会话上下文输出结构化参数，后台查询事实、计算金额并校验对象来源。订阅费用使用 `quote_subscriptions`，由模型把期限换成整月，后台返回记录依据、估算和套餐资料缺失说明。转账和其他变更仍须用户确认后执行。

新增业务可沿用参数校验、查询/预演/确认权限、界面卡片和执行回执。联系人备注是未来独立能力，不与 `transfer.note` 混用。详见 [业务框架说明](docs/business-framework.md)。


## 联系人目录

“模拟银行”旁的“联系人”入口默认收起，两个面板互斥。姓名仅显示姓氏，电话和银行卡仅显示尾号，逐人点击眼睛读取完整模拟信息；再次收起后恢复脱敏。支持保存备注并保留原名，点击联系人新建对话询问操作。

左上角加号可新增联系人，同名必须选择合并到已有人员或作为另一个人保存。每人右侧加号可追加电话或银行卡；多个银行账户、电话都属于同一个人员，转账时多卡必须明确选择。新增陈悦在模拟商业银行的账户（尾号5810），与原演示银行账户（2468）共用手机号。现在初始共有8位人员、9个银行账户。

## 应用注册与密码

联系人右侧齿轮为应用设置。首次打开先注册或短信登录，再引导添加联系人、设置四位交易密码并重复确认。验证码显示在右下角模拟短信中。默认开启启动解锁；资金操作始终需要交易密码。详见 [应用安全说明](docs/application-security.md)。已有银行数据保留，更新不会代设用户名、手机号或密码。

## 多用户与演示账号

演示文档账号保留原有模拟银行状态。其他手机号注册后，银行账户、联系人、订阅、持仓、风险测评和历史业务均为空；公共理财产品目录保持可见。所有用户数据与设置按账号自动保存，退出、切换或重启不会互相覆盖。顶部中间显示“您好，用户名”。

退出登录后，密码解锁页提供“没有账号？注册应用”和“使用手机号短信登录”。点击注册直接进入注册表单。

应用设置的“个人信息”支持修改用户名，保存后立即更新顶部中间问候语，并在后续登录时保留。

## 联系人关系与 AI 添加

联系人支持关系分类、生日、性别、特别关注，面板提供分类和关注筛选。姓名足以创建联系人，其他信息可选并可后续补充；通过聊天也能添加，先检查同名，再核对确认卡保存，无需打开联系人面板。详见 [联系人资料说明](docs/contact-profiles.md)。


## 当前官方权限补齐

修改已设置的支付密码是红色操作，须旧密码加本次修改绑定的模拟短信双重验证。注册首次设置沿用已完成的手机号短信引导。

订阅列表、费用与套餐查询按赛题列为黄色，聊天和账户面板都先展示确认卡，明确确认后才读取并返回明细，不需支付密码、不扣款；取消订阅独立确认。普通账户快照不返回订阅明细。确认后的面板列表标明查询时间，重新查询仍需确认。详见 [官方权限补齐说明](docs/官方权限补齐：改密与订阅查询.md)。


## 自定义账单分析与默认图表

在聊天框说明时间范围、筛选条件和比较方式，系统默认配图：趋势用折线，分类占比用环形，两期对比用柱状图，无需再说“画图”。固定月度和年度账单也自动展示适用图表。

自定义分析由模型生成受限Python子集代码，在独立计算进程的白名单解释器中运行，并与后台独立汇总逐项核对。它不是任意Python运行环境；不开放导入、文件、网络、数据库或资金操作。详见 [分析与沙盒边界](docs/自定义账单分析与受限代码沙盒.md)。

## 部分成功任务收尾

多步骤任务部分成功后失败时，会依据实际回执和流水展示收尾卡。可保留已完成并结束剩余步骤，重新规划未完成项目，或对支持退订的旅行整单重新确认并验证后退款。不会自动撤销转账或重复执行已成功操作。详见 [部分成功任务收尾](docs/部分成功任务收尾.md)。

## 审计防篡改

管理员工作台的操作审计新增防篡改校验。银行侧关键变更追加哈希链，管理员独立保存Ed25519签名检查点，核对当前数据、已签名前缀及记录数；异常不重新签名。当前同机部署不等同绝对不可篡改或WORM存储。详见 [部署、校验与边界说明](docs/审计防篡改与签名检查点.md)。
