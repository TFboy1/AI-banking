# 有数 · 极简 AI Banking

一个聊天页面，加上可收起的历史会话列表和模拟银行面板。六类能力由同一个 Agent 调用银行工具完成：转账、账单分析、理财申赎、卡片管理、订阅管理和跨场景任务。

## 启动

环境要求：Windows PowerShell、uv、Node.js 22.12+。后端使用 Python 3.11。

```powershell
# 在项目根目录运行：安装依赖、构建前端、启动后端并托管构建产物
.\scripts\start.ps1

# 已经安装和构建时，可以跳过前端构建
.\scripts\start.ps1 -SkipBuild
```

打开 **http://127.0.0.1:8000**。停止服务使用 Ctrl+C。前端和 API 由同一服务提供，不必另外启动前端开发服务器。

`uv` 复用全局缓存，安装优先使用 hardlink；Windows 上缓存与项目跨盘时会自动退回复制。源码、配置、文档均使用 UTF-8。

### 配置真实大模型

启动脚本会在 `.env` 不存在时从 `.env.example` 复制。填写下列内容，然后重启后端：

```dotenv
LLM_BASE_URL=https://你的兼容接口地址/v1
LLM_API_KEY=你的密钥
LLM_MODEL=你的模型名
```

`LLM_BASE_URL` 保留服务商要求的版本前缀，不要带 `/chat/completions`。接口须支持 OpenAI 兼容的 Chat Completions。密钥只读入后端，不返回前端。

`LLM_TOOL_MODE=auto` 默认先使用原生 `tools/tool_calls`。如果模型在尚未调用银行工具时只返回文字，后端会让同一模型输出 JSON 工具计划，再经过原有工具白名单、参数验证和确认流程。没有查询证据的第一段文字不会直接展示。对原生工具调用不稳定、支持 `response_format: json_object` 的接口，可设置 `LLM_TOOL_MODE=structured` 直接走此协议；原生工具支持完整的服务可设置 `native`。结构化响应无效或缺少查询依据时明确报错，不能据此更改银行数据。

没有配置模型时，页面会明确显示“未配置”。你仍可打开模拟银行面板查看数据、查询账单或重置沙箱；聊天不会伪造 AI 响应或交易成功。设置中的“已配置”仅表示配置齐全，网络连通在实际请求时检查。

## 演示方法

先展开右上角“模拟银行”，再在聊天中输入需求。**变更操作只有点击确认卡片后才执行。**

| 场景 | 示例 |
| --- | --- |
| 智能转账 | 给张三转 200 元，备注晚餐 AA。 |
| 账单分析 | 这个月的钱花在哪了？有没有重复扣费？ |
| 理财 | 比较一下现有理财产品，我想买 1000 元。 |
| 风险问答 | 我计划投资三年以上，可以接受较大亏损，投资经验较丰富。 |
| 理财赎回 | 查询我的持仓，再赎回安心现金 100 份。 |
| 卡片管理 | 冻结我的日常借记卡。 / 把银行卡日支付限额设成 500 元。 |
| 订阅管理 | 列出我的自动续费，取消星河视频会员。 |
| 跨场景 | 查一下订阅支出，取消星河视频会员，再转 500 元到储蓄账户。 |
| 歧义澄清 | 给李明转 100 元。（种子数据中有两位李明） |
| 操作前预演 | 我想买台 6000 元的电脑，下个月至少留 3000 元生活费。 |
| 目标储蓄 | 帮我月底累计存下 2000 元，房租和生活费不能受影响。 |
| 改口补差额 | 先确认存 500 元，再说“改成这个目标总共存 700 元”。 |
| 条件触发 | 工资到账后提醒我存钱，但要留够 3000 元生活费。 |
| 申购受阻诊断 | 我想买 1000 元远见成长，为什么现在买不了？ |
| 转账受阻诊断 | 载入缺口演示场景后，为什么给张三转 100 元办不了？ |

初始数据：日常账户 ¥12,860.50、储蓄账户 ¥8,200.00、安心现金持仓 2,000 份，以及最近三个月的历史账单。张三的演示手机号为 `13800001111`。所有联系人、银行卡、资金、产品与交易都是模拟数据。

每个组合任务逐步执行：一项完成后才继续下一项。任一步失败都会停止后续步骤，已经完成的操作和回执保留。发送新消息会取消上一条需求中尚未确认的操作；已经执行的操作不会撤销。

### 资金计划演示

1. 在“模拟银行”中点击“载入缺口演示场景”。业务日期会固定为 2026-09-30，日常账户 6256 元已全部安排给房租、生活费与订阅。
2. 在聊天中发送“我想买台 6000 元的电脑，下个月至少留 3000 元生活费”。助手会从历史流水推断工资和房租，展示当前执行与工资到账后执行两种方案。
3. 在方案卡点击“挑战工资延期”或“测试突发支出”。挑战只做单因素精确搜索，并标明范围；修复建议会生成新的计划版本并重新验证。
   方案卡可切换执行时点，查看逐事件的可自由安排余额曲线、首次资金缺口及计算依据。
4. 采用可行方案后，资金预留开始生效；实际消费或转存仍需单独确认。工资尚未实际到账时，不会提前生成依赖工资的扣款确认。
5. 登记“工资到账时提醒”，再从模拟银行触发工资到账。系统只入账一次，按最新账务生成待采纳建议；用户采纳后才出现转存确认卡。

计划、承诺与成功交易回执持久化并跨会话共享。另一会话尝试使用已安排资金时，确认阶段会重新检查并阻止冲突；查询 `list_plans` 可看到承诺来源、期限及储蓄目标实际完成额。

账单、资金方案与确认卡可展开“为什么这样建议”，查看银行记录、检查项与结论。转账和申购诊断只读取当前状态，一次列出已知阻碍；卡片上的下一步按钮只填入聊天草稿，不会自动发送或执行。模型上下文中的已知联系人手机号会替换为联系人编号，查询结果只展示脱敏手机号。

### 会话管理

- 点击顶部“新会话”或会话列表中的“新建会话”，开始一段独立对话。
- 顶部的会话图标可展开历史列表，支持切换、重命名和删除。第一条消息会自动成为会话标题，刷新和重启保留记录。
- 各会话的模型上下文、消息和待确认操作独立；余额、持仓、卡片和交易流水属于同一个演示身份，各会话共用。
- 切换或新建会话不会取消原会话的待确认操作，可返回原会话继续确认。删除会话会取消尚未确认的操作；已完成的银行交易及审计回执保留。仍在处理请求的会话需等待结束后才能删除。
- “重置演示数据”会清空所有会话并重置整个银行沙箱。服务启动会自动迁移旧数据库，保留已有聊天与资金数据。

## 业务与执行约定

- 金额以整数“分”存储；工具金额参数使用元的字符串。余额、流水、持仓与操作回执由后端事务更新。
- 确认卡片保存已解析的收款人、金额等参数，15 分钟有效。确认时重新检查余额、日限额、卡片状态及产品风险。同一确认重复提交只会执行一次。
- 风险问卷根据用户三项回答生成 R1–R4 演示等级；申购必须匹配等级。初始未测评，赎回不受新增风险测评限制。
- 理财采用固定模拟净值、即时结算；份额保留 4 位。不足一分的申购款向上取整，赎回款向下取整，不计额外手续费。该规则用于本地沙箱，不表示真实产品条款。
- 冻结银行卡后，关联账户的转账和申购会被阻止；解冻后恢复。日限额只统计本次演示产生的支付，种子历史流水不占本次支付额度。
- 本人账户互转及理财本金进出不计入消费统计；异常提示保留交易依据，是待核对线索。
- 订阅识别基于跨月扣费记录并核对协议。取消会关闭模拟代扣协议及后续扣费日期，不退款。首版不连接真实商户，也不运行真实续费扣款。
- 对话、任务、待确认操作和回执均持久化。重启保留待确认卡片；处理中被中断的任务明确标记失败，已确认的操作不会自动重放。
- 每个会话同时接受一条处理中请求，多个会话的任务由后端队列依次处理。所有数据属于一个本地演示身份，浏览器使用 HttpOnly 连接 Cookie；应用默认监听 `127.0.0.1`。
- 展示的是简短回复、银行数据及回执，不展示模型内部推理内容。未授权工具、额外伪造参数及绕过确认的变更请求会被拒绝。

## 本地开发

```powershell
# 后端
uv sync --frozen --link-mode hardlink
uv run uvicorn banking.main:app --host 127.0.0.1 --port 8000

# 需要前端热更新时，在另一个终端运行
cd frontend
npm ci
npm run dev
```

开发服务器为 `http://127.0.0.1:5173`，`/api` 代理到 8000。若 5173 被其他项目占用，可以继续使用 8000 上的构建版本。

主要代码：`backend/banking/bank.py` 为银行工具，`agent.py` 为模型工具循环和确认流程，`main.py` 为 API，`frontend/src/App.vue` 为单页对话。

API 文档：`http://127.0.0.1:8000/docs`。

| 接口 | 用途 |
| --- | --- |
| `GET /api/bootstrap?conversation_id=会话ID` | 选择并获取会话、历史消息、会话列表、配置状态与银行快照；省略 ID 恢复最近选择 |
| `GET /api/conversations` | 获取历史会话列表及各自任务状态 |
| `POST /api/conversations` | 新建会话，可选 `title` |
| `PATCH /api/conversations/{id}` | 更新会话标题 |
| `DELETE /api/conversations/{id}` | 删除会话入口，取消待确认操作，保留银行审计数据 |
| `POST /api/messages` | 提交 `text` 和 `conversation_id`，返回任务 ID |
| `GET /api/events?after=事件序号&conversation_id=会话ID` | 当前会话的 SSE 消息、任务及共用银行状态事件，支持 Last-Event-ID 恢复 |
| `POST /api/approvals/{id}/decision` | 提交 `decision` 和原 `conversation_id`，确认或取消固定参数的待执行操作 |
| `GET /api/bank` | 获取银行模拟状态 |
| `POST /api/sandbox/inspect` | 从模拟面板发起只读查询 |
| `POST /api/sandbox/reset` | 确认后恢复初始数据并清空聊天 |
| `GET /api/plans` / `GET /api/plans/{id}` | 查询计划、当前版本、承诺和执行进度 |
| `POST /api/plans/preview` | 用结构化参数生成现金流预演 |
| `POST /api/plans/{id}/actions` | 挑战、应用修复、采用计划、登记规则或请求执行 |
| `POST /api/sandbox/events` | 提交可去重的模拟工资到账事件 |
| `POST /api/sandbox/scenario` | 载入固定的资金缺口演示场景 |
| `POST /api/notifications/{id}/adopt` | 采纳条件触发建议并生成转存确认 |

## 验证

```powershell
.\scripts\check.ps1
```

执行后端静态检查、pytest，以及前端 `vue-tsc --noEmit && vite build`。测试使用临时数据库与明确的模型替身，不访问真实银行、模型或飞书。包含资金守恒、金额精度、并发确认、风险匹配、流程中断、恶意工具调用和跨渠道确认等场景。

另可运行 `uv run python scripts/smoke_backend.py`，在临时数据库和临时端口检查实际 HTTP/SSE 事件流。不会修改日常演示数据库。

已配置模型时，可运行 `uv run python scripts/smoke_model.py`，以当前真实模型验证本月账单、带历史错误的重试、独立会话查询与转账确认生成。检查使用临时数据库，不确认任何资金变更；会产生真实模型请求。它不属于默认离线测试。

**不执行浏览器自动化或前端交互验证，前端由你自行验证。** 真实模型和飞书连通需在配置凭证后另行检查。
