# 独立旅行演示平台

启动有数（8000）后，运行 `scripts/start-travel.cmd`，打开 http://127.0.0.1:8004/ 。它是仿携程功能的虚构演示站，不连接真实携程；所有班次、酒店、评分、价格均为测试数据，不真实出票或提供住宿。

## 关联和使用

旅行站独立手机号短信登录，演示手机号为11111111111；验证码在右下角模拟短信显示。有数设置生成的同一个8位通用同步码，可分别用于证券、外卖和旅行站。每个有数账户对应一个旅行账户，订单相互隔离。

在有数说：“10月25日从上海去杭州，10月28日返回，住西湖区，2人1间，推荐机票、动车和酒店。”日期需为明天至180天内，入住1至30晚。支持20个演示城市及其区域。缺少出发地、日期、区域先补问；无区域偏好可说“不限”。未指定人数/房间数时先展示1人1间报价并请核对。

有数通过旅行API查询往返交通和酒店，说明价格、时段、区域等推荐理由。每一程飞机与动车二选一，不重复购买。用户选择方案后，后端按人数、间数、晚数汇总，并生成确认卡。支付窗口选择付款账户，验证密码；超过固定1000元的单笔消费门槛另需模拟短信。预订和扣款在同一个数据库事务提交，订单同步到旅行站“我的行程”。

也可以在旅行站搜索和选择三个项目，复制生成的指令到有数。有数会重新查询并核对选择，站点不会直接扣款。报价有效5分钟、搜索有效30分钟；日期、城市、区域、人数或房间数变化需重新搜索。

可在支付窗口选择定时支付，必须在出发日之前；到点重新查询和核对同一方案，价格或内容变化、行程已过期、余额不足、账户锁定则停止，不自动重试。授权时不扣款、不冻结余额。任务中断、审计、恢复与现有业务使用同一流程，恢复时重新报价并验证，已成功预订不重复执行。

## 主要API

旅行站：`GET /api/travel/session`、`POST /api/travel/auth/sms`、`POST /api/travel/auth/login`、`POST /api/travel/connect`、`POST /api/travel/search`、`GET /api/travel/orders`。

有数工具：`get_travel_context`、`search_travel_options`、`quote_travel_order`、`place_travel_order`、`get_travel_orders`。内部搜索、报价和订单接口校验旅行平台密钥；报价绑定用户、会话、有效期，付款参数和金额由后端确定。

当前仅支持成人往返交通加酒店的组合演示，不包含儿童票、证件采集、真实座位库存、单程/纯酒店订单；不适合用来执行真实出行安排。

## 免费退改

当前所有演示机票、动车和酒店退改手续费均为0。改签先查原订单，再查询新方案、计算只更改所选部分的差价；确认验证后更新同一订单，不新增重复订单。贵的补差价，便宜的原路退差价，同价不产生资金流水。整单退订确认验证后退回剩余全部实付；不同支付来源按剩余支付记录退款，原分类账户删除或卡片解绑时退到日常账户并在确认卡说明。旧订单版本、旧改签报价和已使用报价不能重复办理。

可以说：‘把返程改到29号下午动车，去程和酒店不变’，或‘整单免费退订’。仅支持整单退订，暂不支持只退某一张票或酒店项目；此类请求先说明并澄清，不自动整单退款。退改当前立即确认办理，不支持定时退改。
