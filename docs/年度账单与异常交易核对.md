# 年度账单与异常交易核对

## 用法

在有数对话中输入“今年的钱花在哪里了”“生成2025年的年度账单”“看看上个月账单”“最近一周有没有重复扣款”。同一会话可以继续问“今年的呢”。报告属于只读查询，不创建待支付操作。

统一使用 `analyze_bills`：month 为 YYYY-MM，year 为整数年份，days 为最近1至365个自然日（含今日），三者只能提供一个；均省略为本月。最近异常未指定时间默认查询最近30天。今年、去年和上个月按系统北京时间解析。

## 统计口径

- 年度报告包括12个月的收入、支出与净收支，消费分类、前五个主要支出对象，以及对应记录数量。当前年度只纳入查询时刻之前的已有流水，未来月份明确显示“未到月份”；无记录月份显示“无流水记录”，不能据此认定实际支出为零。
- 本人账户互转不计入日常收支，理财、证券投资与证券卖出单列投资资金流出和回笼。投资回笼可能包含收益，此处不冒充已独立核算的投资利润。
- 使用北京时间自然月、自然年与自然日；UTC或带其他偏移的流水先统一时间，不用字符串前缀判断月份。
- 月度、年度及近期查询共用一份计算逻辑；金额以分进行整数加总。收入与支出均为已有流水口径，报告不修改账户和交易数据。

## 异常规则

| 线索 | 可复核条件 |
| --- | --- |
| 大额支出 | 单笔日常支出达到3000元 |
| 订阅重复扣费 | 同一自然月、同订阅、同金额出现多笔支出；跨月正常续费不合并判断 |
| 短时重复支付 | 同对象、同类别、同金额10分钟内出现至少两笔支出 |
| 短时多笔转账 | 10分钟内出现至少3笔对外转账；本人互转和投资流转不参与 |
| 高于历史水平 | 仅比较本笔之前90天最近20笔同类非转账日常支出；至少5笔时才计算中位数。本笔至少200元并达到中位数3倍时提示 |

以上都是演示规则，命中不等于欺诈，未命中也不代表安全；正常分次支付也可能命中。历史不足会明确显示不作历史水平判断，不以固定阈值代替历史基线。

每条线索可以展开实际流水，包括对象、金额、北京时间、类别、备注和编号。历史比较另附此前同类支出明细，来源编号保存在报告中。相同交易可能命中不同规则，因此线索数量不等于异常交易数量。

报告只提供核对依据，不自动冻结账户、取消交易或发起退款。不同用户只访问各自分库中的流水。

## 验证

使用临时账户验证年度与月度加总、投资本金排除、北京时间换日和换年、未来流水排除、异常金额及原始流水一致性、历史样本不足和无未来数据泄漏、用户隔离与只读查询。既有账单、日报、对话和诊断相关测试完成回归。

当前配置的大模型完成9类表达评测，覆盖今年、去年、指定年度、上个月、本月、最近30天、最近一周，以及多轮跨年追问和沿用上一份账单范围。上下文范围修正后已复测。评测没有确认交易，临时账户余额和交易记录均保持不变。

界面验证覆盖320、390、844和1440像素宽度，检查年度趋势、明细局部横向滚动、异常流水与历史依据展开、空数据提示和脚本错误。
