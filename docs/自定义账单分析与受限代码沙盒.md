# 自定义账单分析与默认图表

在有数现有聊天框提出需求，例如“10月1日到17日按周看看消费变化”“对比本月和上月同期各类支出”“自定义分析本月分类占比”。不需要另外要求画图。固定月度和年度报告也自动补充适合的趋势、分类图。

支持日期范围、日／周／月分组、支出／收入／净收支、类别筛选、明确商户或用途关键词筛选、两个时间段按类别对比。范围不明确时需要澄清；追问沿用同会话明确报告范围。首版不支持任意外部数据、任意Python库或预测收益。外卖只匹配账单中的外卖用途标记，不把全部餐饮当外卖。

## 数据与图表

1. 模型通过 `get_bill_analysis_data` 提出结构化分析范围，后台只读取该用户数据库、当前对话的已有流水，统一排除本人内部划转和理财／证券本金。
2. 数据集按对话保存15分钟有效快照。给模型只提供样本及代码契约；代码执行输入仅含分组、系列及整数分金额，不提供姓名、手机号、银行卡、账户密码、交易说明或银行数据库连接。
3. 模型生成计算代码，并调用 `run_bill_analysis_code`。
4. 后台在独立子进程中运行受限解释器，输出分组金额。再与后台独立汇总逐项比较，分组、值、类型均一致才展示。
5. 趋势默认折线图，非负类别占比默认环形图，两期比较及有负数的类别结果默认柱状图。图例和可展开数据表提供准确金额，分析依据默认收起。

空数据不造图、不把缺失流水说成实际零消费。范围包含未结束的时间时注明截至查询时刻。周分组以周一标记，首尾周可能不足7天。不同区间的金额差异不直接解释为同等时长的增长；对比期没有正金额时不计算百分比。

## 沙盒的具体边界

这是**受限Python语法子集的逻辑隔离**，不是Docker、虚拟机，也不运行任意完整Python程序。模型代码从不传入Python的`exec`或`eval`。

- 只解释赋值、有限`for`、`if`、字典索引、受限整数运算和指定的`len/get`函数。
- 全树检查禁止导入、属性／方法访问、任意函数调用、函数或类定义、`while`、推导式及反射入口；未执行分支也会检查。
- 输入为不可修改的映射快照；仅可写自建标量字典。不能打开文件、联网、调用系统命令、读取环境变量、连接银行数据库或交易。
- 工作进程使用`-I -S`、临时工作目录、精简环境；不继承模型密钥环境变量。没有向生成程序暴露主进程对象。
- 代码不超过12000字符、AST不超过600节点、计算不超过600000解释步骤／3秒；父进程5秒超时会终止子进程。输入、输出、集合、变量及分组均设上限，并发执行最多2个。
- 不宣称有操作系统级内存或容器隔离。内存风险由受限语法、输入大小、集合／分配预算限制；如以后允许通用Python或第三方库，必须换成更强隔离环境。

执行记录保存代码、代码校验、数据校验、耗时和状态。失败、被停止或核对不一致时不展示分析结果，不修改任何资金。后台重启将遗留运行记录标记中断，用户“继续”时由既有任务恢复流程重新核实。没有新增公开的任意代码执行HTTP接口；既有聊天身份和对话边界仍由后台执行。

订阅协议／费用查询继续走黄色确认；分析工具只提供历史账单统计，不接受代扣协议、余额或交易指令。日报、定时付款及生日预算规则不变。

## 验证与预览

`test_custom_analysis.py`覆盖真实子进程计算、导入／文件／属性逃逸拒绝、输入只读、计算预算、伪造金额拦截、数据过期、跨对话拒绝、空数据、分类和净收支口径、聊天双工具调用与余额不变。界面用隔离演示数据验证桌面、手机和横屏，不给现有用户添加测试流水。
