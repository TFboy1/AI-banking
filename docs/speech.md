# 本地语音输入

有数网页输入框旁新增麦克风。触屏设备长按录音、松手结束；鼠标设备点击开始、再次点击方块结束。录音结束后只把识别文字回填当前输入框，用户核对姓名、金额后自行发送，不自动创建任务或执行交易。

每段最长60秒，结束或取消会关闭麦克风；切换会话、退出登录、页面进入后台时取消正在录音的内容。首次授权麦克风时若已经松手，这次录音取消，授权后重新长按。识别中可取消；迟到结果不会进入别的会话。原草稿保留，识别文字追加到草稿后。

页面加载时提前创建音频处理组件，不申请权限、不采集声音。长按或点击时并行唤醒音频组件和申请麦克风；准备好且手指仍按住才开始手机录音。正常结束后暂停并复用音频组件，麦克风音轨立即停止；进入后台或离开组件时销毁音频组件。启动等待超过15秒提示重试，迟到的授权结果会关闭音轨。首次权限弹窗和系统硬件启动仍可能需要等待。

## 部署

1. 在项目根目录运行 `uv sync --extra speech`，或在当前Python环境安装 `sherpa-onnx==1.13.8` 和 `numpy>=2,<3`；Windows还需要同版本 `sherpa-onnx-core`。依赖锁已包含这些版本，Windows启动脚本会安装speech额外依赖。
2. 运行 `python scripts/setup_speech.py`（uv用户使用 `uv run --extra speech python scripts/setup_speech.py`），下载约237MB的SenseVoice INT8模型和词表。固定模型版本并验证SHA256，不在处理用户请求时自动下载。
3. 启动有数。默认模型目录是项目下 `data/speech`；可用 `SPEECH_MODEL_DIR` 指定另一个本地目录。模型就绪后离线推理，不调用付费语音接口。
4. 手机通过HTTPS打开有数并允许麦克风；本机可用localhost。具体手机浏览器及飞书内置浏览器仍需实机验证，不支持录音时继续用文字输入。

部署到本机的模型文件已安装；交付源码包提供安装脚本，不重复打包大模型权重。

## 接口与边界

- `GET /api/speech/status`：登录后查看模型是否就绪。
- `POST /api/speech/transcribe`：登录解锁后上传原始 `audio/wav` 请求体；16kHz、单声道、16位PCM，0.2至60秒，约1.93MB上限。浏览器通过Web Audio采集并转换，不依赖服务器FFmpeg。
- 返回识别文字，不创建聊天消息、操作确认或交易任务；完整接入现有用户隔离、来源检查和系统锁定机制。
- 每用户每分钟最多10次请求，整个进程同一时刻只处理一段识别；上传超时15秒，客户端识别等待上限90秒。
- 原始录音和识别文本不写数据库、不保存临时文件。仅记录成功识别的时长、文字长度等审计元数据；用户点击发送后，文字才作为普通聊天消息保存。
- 识别可能出错，尤其同音姓名、金额、嘈杂场景；不把转写当作交易确认。交易继续使用原有确认、密码和短信规则。

## 开源来源

- [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)，运行库为Apache-2.0许可。
- [SenseVoice](https://github.com/QwenAudio/SenseVoice)，模型许可独立于运行库；应遵守官方模型许可及署名要求。
- 使用[sherpa官方文档](https://k2-fsa.github.io/sherpa/onnx/sense-voice/pretrained.html)链接的 `csukuangfj/sherpa-onnx-sense-voice-zh-en-ja-ko-yue-int8-2025-09-09`，固定版本 `355f4d4884d8afd08aef04b9007a8556d7b463b2`。模型校验值及来源另保存在模型目录SOURCE.txt中。

已验证：登录与音频边界、限流、忙碌状态、缺失模型不编造结果、转写不改资金；公开中文样例真实CPU推理；浏览器模拟麦克风、电脑点击录音、手机长按松手、拒绝权限和取消、切换会话、320px布局。未使用用户的真实麦克风或声音进行自动化测试。
