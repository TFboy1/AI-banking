# 独立外卖演示站

访问地址：http://127.0.0.1:8002/。仿美团风格，名称为“有数外卖”，明确标注沙箱与非真实订单。

## 使用

1. 启动有数银行8000与外卖站8002，证券站8001可独立继续运行。Windows双击scripts/start-food.cmd启动外卖站；其他环境可运行python -m uvicorn banking.food_site:app --app-dir backend --host 127.0.0.1 --port 8002。
2. 外卖站用手机号登录，验证码在右下角演示短信中显示。默认演示手机号11111111111；新手机号自动新建空账户。
3. 有数应用设置生成“平台通用同步码”，到外卖站“连接有数账户”输入。同一码供证券和外卖分别使用，每个平台一次、五分钟有效，重新生成使旧码统一失效。每个有数账号与外卖账号一对一。
4. 在外卖站选择演示位置，或在有数对话中说“将外卖演示位置设为陆家嘴”。现有位置：上海陆家嘴、人民广场、徐家汇，全部明确标注为演示地址，不读取真实GPS。
5. 对话示例：“帮我看看附近能点黄焖鸡饭的店铺”；选择店铺后“看看小满饭堂陆家嘴店的菜单”；“帮我在小满饭堂陆家嘴店下单两份招牌黄焖鸡饭，少辣”。助手查菜单，后台统计并报价，生成确认卡，支付弹窗选择账户并验证密码后创建虚拟订单。超过用户设置门槛需短信验证。
6. 外卖站“我的订单”可刷新查看；切回窗口自动重新读取。网页菜单也能选份数并生成可复制的有数点餐指令，网页本身不绕过银行支付验证。

## 范围

9家虚拟门店，每家6道菜，按演示经纬度计算距离并按各店4公里配送范围筛选，支持关键词搜索、菜品数量、备注、餐费、每份打包费、配送费与起送金额。所有价格与配送预计时间都是演示数据，未连接美团或商家，没有真实配送。

## 接口与执行

独立外卖站保存手机号账号、会话、账户关联和演示位置，使用独立food_auth Cookie、数据库food-users.sqlite3及桥接密钥.food-bridge-key。银行和证券Cookie不能登录外卖站。公开API路径/api/food/*，内部授权API路径/internal/food/*。内部接口需要x-food-key，浏览器不持有该密钥。

银行模型工具：get_food_context、set_food_location、search_food_shops、get_food_menu、quote_food_order、place_food_order、get_food_orders。位置和菜单从外卖API读入，有数不让模型编造费用。先有真实报价，再用当前用户、当前会话的quote_id下单。报价五分钟有效；缺位置、超配送范围、菜品不属于店铺、未达起送、非法数量、余额不足或卡片受限时不下单。单道菜上限20份，单笔最多100份。

银行每用户数据库保存food_quotes和food_orders，虚拟订单记录、余额扣除、账单流水和执行回执在同一数据库事务中提交。订单号与报价号唯一约束，防重复扣款；外卖站订单API从银行按已关联owner读取真实提交记录，不单独伪造第二份订单。确认前取消不会扣款。没有执行回执时拦截“已下单”宣称。订单收货地址按确认卡中的演示地址固定，之后改位置不改变这张订单。账单分类为餐饮。

付款验证沿用银行支付密码、分级短信策略、付款账户与卡片限制、失败锁定、确认和幂等机制。单用户和多用户银行均有/internal/food/orders授权接口；多用户模式按food_owner寻找所属用户数据库，不依靠浏览器传入银行用户名。

目前不实现退款、取消已付款订单、真实库存消耗、配送调度、优惠券或第三方真实支付；订单状态为“模拟已下单”，不会假装骑手正在送餐。

测试覆盖：演示登录关联、一次性同步码、一对一绑定、不同账号位置和订单隔离、多租户银行订单路由、搜索配送范围、数量及费用、确认前不扣款、支付密码、红色短信、重复确认、报价到期、取消确认、无效菜品与数量、起送金额及跨会话报价保护。页面另验证完整操作和手机布局。
