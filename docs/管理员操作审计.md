# 管理员操作审计

进入 http://127.0.0.1:8003 ，使用管理员密码登录，点击顶部“操作审计”。默认密码沿用 `000000`。

## 可以查看什么

- 按用户、对话标题、最新任务状态、对话更新日期筛选，分页查看对话。
- 单段对话的用户请求、显式 DAG 节点和依赖、后台查询依据、确认卡、用户确认或取消、密码与模拟短信验证记录、执行回执、实际记账流水、中断与恢复检查点、人工接入记录。
- 账户安全页：所选用户最近300条安全事件，包括无法归属具体对话的事件。
- 管理员记录页：最近300条登录、接入、回复、审核、查看及导出操作，可按用户筛选。
- 单段对话导出 CSV 时间线，或包含步骤、操作、回执、流水和时间线的 JSON 文件。

处理步骤与详细依据默认折叠。查看记录不会执行交易、恢复任务或修改资金。

## 资金核对口径

按对话内确认操作编号关联已落账流水，仅匹配相同 `action_id` 或以 `操作编号:` 开头的业务子流水，不使用通配符匹配。证券买卖、外卖等带后缀的流水同样纳入。

恢复任务共享的成功操作不会重复累计，沿用的 DAG 节点标注“沿用已完成步骤”，不重新记为一次执行。汇总中的扣款和入账包含本人账户互转，不能解释为消费或日常收入。

对外转账有本方扣款和模拟成功回执，但没有收款方独立流水时，明确标注此情况，不推断收款方已经独立确认到账。对话里模型自由文本声称的金额不作为资金依据。操作状态、回执或流水不一致时显示待人工核查提示。

## 验证与历史记录

新增记录保留用户提交确认时的风险等级、固定门槛、当日累计转账金额（转账类）、规则版本、付款来源及是否需要验证。规则升级不会改变此前保存的判断依据；当前不支持用户修改门槛。支付密码验证通过及失败关联操作编号；短信沿用已有发送、通过事件，补充验证失败原因。

旧记录没有的验证日志不补造，也不根据当前门槛推断旧交易当时的风险等级。账户级安全事件只有明确关联本对话的任务或操作编号时才进入对话时间线，否则只能在“账户安全”查看。这里展示可验证的请求、规划和执行记录，不包含模型内部推理过程。

## 权限与导出

所有审计接口和导出均要求独立管理员登录，由后台按用户编号解析数据库；接口不接受数据库路径。对话编号必须属于指定用户。沿用已有删除规则，不提供已删除对话的审计入口。

导出不包含支付密码、验证码及其散列、登录令牌、服务密钥或完整模型上下文；手机号与卡号等长数字脱敏，密码/验证码字段和对应显示值隐藏。CSV 防止将以 `= + - @` 开头的用户文本当作表格公式。

JSON 包含本次内容的 SHA-256，方便核对导出完整性；这不等于数据库历史不可篡改。查看及导出均追加独立管理员操作记录，重复查看在一分钟内合并记录。

## 验证

自动化测试覆盖真实确认和红色验证、当前门槛变化后的历史判断、流水命名空间、恢复任务去重、模型虚假成功文本不计入资金、跨用户编号隔离、筛选、未登录拒绝、已删除对话拒绝、脱敏、CSV公式保护及导出摘要一致性。界面验证使用独立测试库，不对演示用户执行资金操作。
