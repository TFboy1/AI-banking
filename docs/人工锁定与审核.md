# 人工锁定与解锁审核

本功能是应用访问安全锁，不是数据库文件加密。锁定只影响当前有数用户，其他用户不受影响；证券等平台接口故障熔断不计入人工锁定次数。

## 触发规则

从本次启用开始，两类完整保护事件分别累计：

- 密码或验证码保护：密码连续错误5次，或交易/恢复短信连续错误5次，完整触发一次保护记1次。
- 可疑请求保护：60秒内3次可疑确认或未授权工具请求，完整触发一次保护记1次。

任一类累计第3次，立即锁住当前用户应用。不是单次密码错误记1次，也不是同一窗口的第4、第5次可疑请求再次记保护事件。普通冷却、重新登录或普通短信恢复不会清除累计次数；两类次数不混加。设置中可查看各自的累计次数。

## 锁定范围

聊天、账户、流水、联系人、设置、交易、旧确认、普通短信恢复、模拟重置、对外关联数据及新增关联均受后台限制。已打开的消息流接收到锁定信号后结束；原有任务保存进度并停止，未完成确认失效，已成交记录保持不变。

前台只显示人工申请和人工聊天页面。登录相关接口保留以识别账号，但登录不能解除人工锁定，不能修改密码或通过普通恢复接口自助解锁。刷新、重启、退出登录不清除锁定。

## 演示人工审核

独立客服工作台位于 http://127.0.0.1:8003 ，默认管理员密码为 `000000`。用户填写申请说明后保存为待审核，并建立人工对话。重复提交同一待审申请不会生成重复审核工单。管理员登录后可查看历史记录、与用户交流，在“解锁审核”填写说明并通过或拒绝。用户页没有审核或自助解锁权限。

本机演示管理员可使用独立审核程序，必须指定当前用户的实际数据库文件、申请编号、审核人和原因：

```powershell
python scripts/review_unlock.py --database "当前用户数据库的绝对路径.sqlite3" --request-id "review_申请编号" --decision approve --operator "演示管理员" --reason "已人工核实身份"
```

拒绝申请时将 `approve` 改为 `reject`；系统继续锁定，用户可以补充申请。用户数据库路径可从 `data/accounts.sqlite3` 的 `users.database_path` 查找，不能把账户目录数据库当作用户业务数据库。

只有待审工单可以审核，审核记录保存审核人、时间和原因。通过后清除本轮保护累计与普通交易保护，作废旧短信，要求页面刷新并按应用设置重新解锁；旧交易不会自动重放，继续任务仍须重新核对和确认。

本机审核程序作为备用入口保留；网页审核需独立管理员登录，管理员仅有客服与审核权限，没有银行工具执行权限。管理员密码散列、登录会话及审计独立保存。此功能不提供存储加密或抵御本机管理员直接修改数据库的承诺。
