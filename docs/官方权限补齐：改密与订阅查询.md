# 官方权限补齐：修改密码与订阅查询

本说明更新旧版文档中“修改密码只需旧密码”“订阅查询自动执行”的规则。转账仍沿用固定的北京时间日累计1000元黄／红分级；本次不调整业务范围或代码执行沙箱。

## 红色：修改已设置的支付密码

设置里填写旧密码、新密码、再次输入新密码，点击获取修改密码验证码。旧密码通过后，右下角显示模拟短信。提交时后台再次验证旧密码和短信，均通过才更新密码。

- 验证码绑定当前用户、当前浏览器会话、原密码版本、新密码及手机号。改变新密码需重新获取。
- 五分钟有效；重发间隔六十秒；成功后作废。不能复用登录、交易或其他会话的验证码。
- 连续五次短信错误触发现有交易暂停；硬锁定时不能修改密码。
- 修改成功清理交易验证码，使其他应用会话重新登录；当前会话保持可用。
- 记录发送、拒绝、成功的安全审计，不记录明文密码或验证码。
- 注册后的首次设置仍沿用已完成的手机号短信认证引导，不要求不存在的旧密码。

## 黄色：订阅查询及取消

按赛题表格，`list_subscriptions`和`quote_subscriptions`必须先展示黄色确认卡，明确确认后才查询当前业务状态。不需要支付密码或交易短信，不产生扣款，也不取消订阅。取消订阅保留独立确认。

聊天、模型工具调用和账户面板“查看详情”均经过同一确认链路。普通账户快照不直接附带订阅明细。取消、过期、伪造或跨会话的确认不能取得查询结果。

查询完成后，结果保存在当前对话，并可在账户面板查看这次查询的列表和时间。取消订阅成功后面板要求重新查询，避免展示旧状态；旧对话结果作为历史查询记录保留。重新查询和失败后恢复查询都需要新的明确确认，查询结果不作为已完成资金操作去重。

既有日报续费提醒是用户开启日报后的主动报告，本次不改变日报和生日预算流程。查询确认不会消耗余额或修改订阅状态。

后端验证见 `test_official_permissions.py`。既有订阅算费和上下文测试通过明确确认继续运行，权限边界测试单独验证拒绝绕过。
