# 每日早报

默认开启，每天北京时间09:00生成独立会话，第一条消息为“尊敬的‘用户名’，早上好”。应用设置可关闭或改为00:00–12:00（含12:00，精确到分钟）。无需模型调用或支付验证，不执行任何资金操作。

日报统一以当天00:00为截止点，统计完整昨日00:00–24:00，不纳入当天交易。历史版本用于还原该时点的账户余额、银行卡绑定、理财和股票持仓、订阅与特别关注的联系人资料。不能用生成时的当前余额冒充午夜余额。

日报内容：

- 各资金账户余额及合计，投资估值完整时另列含投资总资产。
- 昨日支出、收入的总额及各笔项目；本人划转、理财和证券本金流转不算日常收支，投资进出单列。
- 理财份额与模拟净值；股票数量、买入成本、截止前最近收盘价、估值及浮动盈亏。行情缺失明确显示不可估值，不编造收益或沿用当天开盘价。
- 截止时仍有效的订阅，其下次扣费日期、距日报当天的天数及本月建议留存金额。逾期协议待核对，保守预留一次本月费用；已取消协议不纳入。
- 特别关注且生日处于未来一个自然月以内的联系人；当天生日也提醒。没有符合条件的人则不显示生日段落。非闰年2月29日按2月末提醒。

## 交付规则

后台运行时自动生成，离线用户不必打开网页或实例化模型。生成后出现在会话列表，并提示“查看日报”，不切换正在处理的对话，也不改动未发送草稿。

同一用户每天最多一份；设置修改、重启、并发扫描不会重复创建。关闭时正在取行情的日报也不会继续提交。删除某天日报后不会自动重建。后台错过时刻但在当日12:00这一分钟结束前启动，会补发当天一份；之后不追补，等待下一天。未完成注册引导或系统被人工安全锁定时不生成。

历史记录从功能安装时开始建立，因此首次生成若截止时间早于记录开始时间，会明确提示历史快照不足，只展示仍有依据的流水，不虚构账户和投资余额。正常安装后次日早报已可使用安装后覆盖的午夜快照。显式重置模拟数据会重建历史起点。

## 实现与验证

- `daily_reports.py`：用户设置、到期判断、确定性汇总、幂等生成及多用户后台任务。
- `report_history.py`：白名单字段的SQLite行版本，源数据和历史记录在同一事务中生效；不复制支付密码、验证码、完整卡号或手机号。
- `stock_valuation.py`：历史截止日估值；只取截止日期之前已确认的收盘价。
- 设置与日报接口遵循现有登录、解锁和用户数据库隔离规则。
- 测试覆盖跨午夜、UTC日期换算、当日变更隔离、投资本金排除、开关与时间边界、并发/重启、关闭竞争、生日边界、行情缺失和历史不足；界面测试使用单独数据库。
