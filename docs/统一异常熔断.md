# 统一异常熔断

安全保护按用户数据库持久化；刷新、退出登录、服务重启或切换对话不会重置保护。另一用户不受影响。

升级规则：密码／验证码保护、可疑请求保护两类分别累计，任一类完整触发3次后，整个用户应用进入人工锁定，只保留人工申请页面；下表中的查询与普通恢复仅适用于尚未升级人工锁定的情况。详见《人工锁定与审核.md》。

| 触发条件 | 保护范围 | 恢复方式 |
| --- | --- | --- |
| 支付密码连续错误5次 | 当前用户资金操作暂停60秒 | 冷却结束后重试，后台自动清理错误计数并记录解除 |
| 交易短信连续错误5次 | 当前验证码作废，当前用户资金操作暂停60秒 | 冷却结束后重新获取验证码 |
| 60秒内3次伪造、未知或跨会话确认，或未授权工具请求 | 当前用户资金操作暂停，需要重新认证 | 重新手机号短信登录，再到设置验证恢复短信 |
| 证券或外卖平台连续3次连接失败、超时、5xx、限流或无效JSON响应 | 对应平台暂停调用60秒 | 冷却后只允许一个探测请求，成功恢复，失败再暂停60秒 |

余额不足、风险等级不符、报价过期、正常平台业务拒绝、主动停止和取消均不计入安全异常次数。正常校验成功重置相应连续错误计数。

后台在资金提交前统一检查，覆盖聊天、页面及直接确认调用。涉及资金归回的分类账户删除也检查保护状态；已有成功回执可查询，取消仍允许，已完成交易不回滚。平台保护期间也不能凭旧报价进行对应平台资金操作，必须先等待并查询恢复。

外部请求以持久化代次和探测租约处理并发：同一用户同一平台仅一次恢复探测；保护开启前发出的迟到成功响应不能错误关闭保护。主动取消网络等待不计为服务失败，取消探测释放租约；进程异常退出后租约到期可再次探测。

设置中的“安全状态”提供暂停原因、倒计时、平台状态及最近50条安全记录。恢复短信绑定当前会话和保护代次，5分钟有效，有发送间隔与错误次数限制；必须先完成保护触发之后的短信登录，不能使用旧登录或旧交易验证码恢复。恢复后原交易仍需重新确认、输入密码，并按交易级别验证新的短信。

任务继续会先检查资金保护；暂停期间不能恢复执行资金步骤，检查点仍保留。保护解除后重新查询、规划和确认，不重复执行已成交步骤。

日志保存失败类型、计数、开启原因、恢复过程及合法任务/操作引用，不保存密码、验证码、上游密钥或原始异常正文。手机号登录短信仍沿用原有登录防滥用限制；本版本统一统计的是交易/应用密码和交易/恢复短信。所有短信为演示短信。

主要实现：`safety.py`、`safety_api.py`；接口为 `GET /api/safety/status`、`POST /api/safety/recovery-sms`、`POST /api/safety/recover`。
