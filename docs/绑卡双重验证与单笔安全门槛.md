# 绑卡双重验证与官方累计安全门槛

- AI与页面添加银行卡均创建待确认操作，验证前不新增卡片和余额。已登录用户必须同时通过四位支付密码、模拟短信验证码；关闭应用锁屏或提高金额门槛不会取消绑卡双重验证。
- 添加银行卡始终为红色验证，沿用验证码有效期、错误次数、发送间隔与参数指纹绑定。验证码绑定该操作、卡号、银行名称、用户身份及安全设置，不能用另一操作的验证码。
- POST /api/cards现在返回待确认消息，确认接口通过双重验证后才返回银行卡回执。没有公开的直接创建入口。模型不接收支付密码或验证码。
- 现行规则：转账按北京时间当日成功累计金额判断，不超过1000元为黄色，超过为红色。门槛固定；本人账户划转计入，取消和失败不计入。转账累计和日期参与本次短信指纹。
- 固定门槛1000元：当天先转600元，再转600元时第二笔需要密码及短信；当天首次转1000元仍为黄色，再转0.01元为红色。理财申购、股票买卖和添加银行卡保留始终红色规则。
- 银行卡自身的支付限额、冻结、余额与资金预留校验继续生效。上述规则为默认开启身份认证的应用模式；关闭整套身份认证的开发测试模式沿用现有测试语义。
- 自动化验证涵盖两个绑卡入口、缺任一验证因素、错误因素、重复确认、余额不提前增加、单笔边界、重复小额转账、既有卡片/转账/证券/外卖流程，并检查页面中的验证弹窗和设置说明。
