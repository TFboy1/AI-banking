# 审计防篡改与签名检查点

管理员工作台 → 操作审计 → 防篡改校验。支持按用户查看、重新校验、签名新增记录和导出公开校验凭据；未登录管理员不能调用这些接口。

## 已实现

银行数据库中的关键表通过事务触发器追加哈希记录：序号、表名、记录标识、操作类型、变更前后指纹、时间、前一条哈希及本条哈希。回滚业务操作时，其审计追加也回滚；已提交的变更才进入连续链。普通SQL不能修改或删除审计链和基线身份。变更业务数据会追加版本，不覆盖已经签名的旧链记录。

范围包括账户余额、银行卡、持仓、对话、消息、任务、确认与回执、资金流水、事件、安全事件、已有定时交易表、旅行与外卖订单等；具体范围在校验页展示。管理员自己的操作日志也建立独立链并签名。不复制密码、验证码、密钥或消息原文到独立存储；存储的是行指纹及链记录元数据。

管理员进程每约10秒核对银行链、当前行指纹和已锚定前缀，将新增链记录副本与Ed25519签名检查点保存在独立目录。银行进程不调用签名器、不读取私钥。检查点包含账户数据库身份、保护范围摘要、记录总数、链头、签名时间和上一检查点摘要。

发现链断裂、签名无效、保护触发器缺失、当前数据不一致、删尾或旧库恢复时，显示异常并拒绝重新签名；不自动清空凭据或重新建立信任。无独立检查点时标为尚未锚定，有新增记录未签名时标为待签名，不显示完整通过。

## 存储和部署

默认位于项目根目录的`audit-witness/`，与`data/`银行数据库分开，已加入Git忽略。可用`AUDIT_WITNESS_PATH`指定管理员专用目录；`AUDIT_WITNESS_ENABLED=false`关闭自动签名，但管理员仍可手动校验、签名。不要把签名私钥提交Git、加入源代码压缩包、发给模型或提供给银行进程。

整个目录应安全备份，包含签名私钥、可信公钥、独立记录副本和检查点。仅备份银行数据库不能恢复信任链。丢失凭据或密钥后不自动重建，恢复可信备份前页面保持异常或不可用。数据库结构升级需要另外设计审计范围迁移，不能把旧基线直接覆盖。

本版仅包含受控的`human_audit`人工动作明细范围扩展：迁移前验证原链与签名，保留原检查点，在新检查点中签署旧范围摘要、新范围及新增表的基线时间；不缩小保护范围、不重置已有记录。不提供任意范围重建接口。迁移中若存储故障导致两处状态不一致，应保留异常并人工恢复可信备份。

## 独立核验

管理员导出JSON校验凭据后，可用`scripts/verify_audit_proof.py`验证检查点签名。必须通过可信渠道预先保存`public.raw`，并用`--public-key`提供；不能把导出文件自带的公钥直接当成可信来源。

签名验证只证明该检查点的记录数、链头、范围及签名时间由相应密钥签发，不单独证明当前数据库完整。当前数据库还需与该可信检查点、记录副本和当前行指纹比较。导出原有审计JSON／CSV的文件SHA-256功能保留，含义仍为文件校验。

## 必须明确的边界

- 首次启用时，将已有数据作为历史基线；不能追溯证明启用前没有被改动。
- 当前为同机独立进程、独立目录，并非操作系统权限隔离、远程可信第三方或WORM存储，不能抵御拥有整台主机权限的管理员。生产需要异机存储、独立凭据与写入权限，并将可信检查点向外部锚定。
- 独立目录受损或整个历史凭据被同时替换、丢弃时，本机无法凭空恢复过去的信任。必须保存离机可信公钥和检查点副本。
- 完整性不等于真实性或完整采集：签名不能证明每个事件业务内容真实，也不能证明系统从未漏记。
- 签名前的时间窗口不能得到已签名历史同等的保护。管理员服务关闭期间，新记录只进入银行侧链，重启并校验通过后才补签。
- 这是审计校验和告警，不改变既有支付验证、交易熔断与人工解锁规则。

## 验证

隔离数据覆盖正常追加与事务回滚、普通SQL修改保护、记录改写／顺序破坏／删尾／重算、当前数据不一致、旧数据库恢复、签名破坏、密钥和凭据丢失、独立公钥核验、用户隔离及管理员登录权限。原有审计导出、退款收尾、支付和日报回归验证继续适用。
