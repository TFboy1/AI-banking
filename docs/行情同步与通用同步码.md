# 行情同步、投资流水与通用关联码

## 股票市值

有数/api/bootstrap和/api/bank不再把股票成本当成当前市值：请求独立证券服务/internal/securities/{owner}/valuation；证券站“我的账户”与该接口共用stock_valuation.value_positions。统一按开盘价、收盘价估值，保留来源、价格类型与时间。持有数量与买入成本仍取银行成交记录。

市值=单股估值×持有股数；浮动盈亏=市值−剩余买入成本；百分比以剩余成本为分母。投资账户合计=理财净值估值+股票估值；账户总余额仍是现金分类和银行卡余额，不因股票涨跌而增加可支付现金。卖出已经计入市值的股票只转换资产形态，不重复增加同一笔浮盈。

有数与证券页面取消30秒轮询，工作日09:30、15:00节点后各同步一次，首次打开补齐缺失数据。银行有效估值缓存到下一个节点，按用户和完整持仓签名隔离；持股数量、成本改变后重新估值。行情源本身有缓存，不代表逐笔实时行情。行情中断保留同一持仓最近估值并标旧；没有历史估值时按成本暂估，market_value/profit为null，不将缺数据当成0元或亏损。

## 月度账单

日常收入、消费、消费分类与大额消费异常检测都排除内部转账、理财、证券投资和证券卖出；完整原始流水保留。新增investment_flows.out_minor/in_minor/net_out_minor/references字段，并在月度账单单列“投资资金流出”“投资资金回笼”。回笼金额可能包含已实现收益，不将全部证券卖出到账冒充日常收入。本次不重写历史流水，不更改余额。

## 一个通用同步码

有数设置只显示“平台通用同步码”。POST /api/connections/pairing-code在当前用户库生成8位码，保存哈希，5分钟有效；证券和外卖都输入这一份码，每个平台各使用一次。生成新码使旧码对所有平台失效；已有账号关联不受影响。旧/api/securities/pairing-code与/api/food/pairing-code兼容入口也改为同一生成逻辑。

各平台连接时通过授权/internal/connections/redeem提交code/platform/platform_user，后台按平台专用密钥校验并返回该用户的对应owner和标签；不同平台的内部owner可以不同，但指向同一有数用户。首次证券兑换不消耗外卖平台的机会，平台内部继续执行一对一绑定、手机号独立登录及数据隔离。多用户模式扫描匹配码所属用户库，再在事务中重新校验并登记该平台兑换；重复、过期、已重新生成或冲突码拒绝。

已关联的证券/外卖账号无需重新绑定。旧平台私有生成接口仅保留原兼容测试路径，不再由有数界面签发独立码。

测试：同一码分别关联两个平台、每平台单次使用、重发失效与到期；涨跌估值与证券平台一致且不改成本或现金；中断时保留估值/成本暂估；股票买卖与理财收付不混入月度日常账单；多用户、旧绑定、买卖、外卖回归。
