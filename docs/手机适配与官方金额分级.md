# 手机浏览器适配与官方金额分级

## 页面范围

有数（8000）、独立证券（8001）、外卖（8002）、旅行（8004）适配手机浏览器。管理员客服工作台（8003）保持原样，不新增原生 APP。

手机导航分行排列，操作按钮至少44像素高，表单字号至少16像素，避免手机输入自动放大。支持安全区域、可滚动弹窗、宽表格局部横向滚动；有数聊天输入区跟随可见视口调整，兼顾软键盘。桌面布局保留。

## 当前有效规则

此说明取代此前文档中“按个人设置的单笔门槛判断转账”的说明。

- 按北京时间当日00:00至次日00:00统计同一有数账号的成功转账，跨会话合并。
- 本笔执行后累计不超过1000元：黄色，明确确认并验证支付密码。
- 本笔执行后累计超过1000元：红色，支付密码及模拟短信验证。
- 1000元恰好为黄色；1000.01元为红色。门槛固定，不提供修改入口，旧修改接口拒绝请求。
- 联系人转账、本人账户与银行卡之间划转、本人账户间划转及储蓄转存计入。本人互转只记一笔转出，不重复统计入账。
- 取消、失败、待确认、尚未执行的预约不计入；模拟种子流水无成功业务回执，不用于累计。
- 统计成功回执关联的转账流水，不能仅凭任务文本、模型回答或预约授权加总。
- 添加银行卡、理财申购、证券买卖仍始终要求密码及短信。其他资金操作超过固定1000元也需要短信。

后台在执行事务内重新判断风险，跨会话同时发起也不能沿用过期的黄色判断。验证码绑定交易参数及当日累计，发生变化须重新验证。不同用户分库统计。

定时转账提前完成支付密码与短信验证，到点按实际执行当天累计及当前业务条件再次复核。授权不扣款，不计入当天转账金额；真正执行成功后才计入。旧版授权因安全规则升级失效，需重新发起授权，不自动按旧口径扣款。

## 迁移与验证

首次升级把旧门槛统一恢复为100000分并提升规则版本，使旧验证码与旧预约授权失效；再次启动不重复提升版本。只调整安全设置，不改账户余额、持仓、银行卡、联系人或订单。

测试使用临时数据库和隔离页面，不操作演示用户资金。覆盖累计边界、跨会话复核、北京时间换日、取消失败排除、本人互转去重、用户隔离、规则迁移、短信与预约执行，以及320/360/390/430像素、横屏和桌面布局。
