# 生日安排与特别关注提醒

通过有数对话说“帮我安排爱人的生日，预算1000元，提前两天提醒我买蛋糕”。系统先按联系人姓名、备注或关系查询，核对保存的生日；多人同关系、未设置生日、月份不匹配均需澄清，不猜测生日或收礼人。

## 预算与通知

- 预览不改变资金；确认计划后，在指定账户预留生日预算，余额不扣减、不转账。
- 自动生日提醒仅针对**当前勾选特别关注**的联系人。系统不会自动开启关注。未关注联系人可手动查看计划、选购商品。
- 提醒前和查询菜单后再次核对关注状态。取消关注会停止后续通知，并隐藏未读提醒提示；已发送的历史会话保留。预算仍保留，可自行取消计划释放。
- 日报的生日栏目也只展示特别关注的联系人，按既有日报截止时点读取资料。
- 到提醒时点，系统新建独立会话，读取已关联的演示外卖账户的收货位置和蛋糕菜单，不抢占当前对话、不清空草稿、不自动下单。
- 提醒按北京时间，默认生日提前2天09:00。后台重启后，未过生日且仍关注的到期计划补发一次；同一计划不重复提醒。服务关闭期间不会发送通知。

## 下单与控制

计划卡展示联系人、生日、提醒、来源账户、预留金额和已消费金额。处理步骤默认收起。暂停保留预算，继续时重新核对，取消或过期释放未用预算。资料或预留发生不一致，标记需重新确认。

选购后重新从演示外卖API报价，必须使用该计划的来源账户，总价不超过预算。确认并按现有策略验证支付密码、所需短信后，才创建虚拟订单并扣虚拟余额。一次成功订单完成本次计划，释放剩余预留；释放预留不产生收入或退款流水。暂停、取消、资料变化后的旧支付确认会重新校验并拒绝执行。失败不自动重试，不会用“模拟消费”伪造蛋糕下单。

流程依赖为：核对联系人 → 确认预留 → 到时提醒 → 查询菜单 → 选购并验证下单。各阶段持久化，可在重启后读取；真正付款使用既有任务DAG、确认与审计流程。人工协助沿用当前对话的转人工入口。

## 边界和接口

同一人员同一次生日不可重复建立进行中或已完成计划。多卡按人员去重。闰日生日在非闰年按2月末；一次计划限定今天起366天内。未关联外卖、未选位置或平台暂不可用时仍可提醒，但不生成订单；用户稍后查询菜单。

工具：`get_birthday_context`、`preview_birthday_plan`、`create_birthday_plan`、`list_birthday_plans`、`manage_birthday_plan`。创建、暂停、继续、取消均经过确认。

受登录保护的接口：`GET /api/birthday-plans`、`POST /api/birthday-plans/{id}/actions`、`GET /api/birthday-plans/notices`、`POST /api/birthday-plans/{id}/seen`。数据跟随现有用户数据库隔离；跨用户计划编号不可访问。

测试见 `backend/tests/test_birthdays.py`，覆盖金额与预留、双重验证、取消后旧支付、重复提醒、取消关注并发、重启、资料变化、平台异常、日期与版本边界。隔离界面及自然语言脚本保存在工作区，不部署测试接口或测试数据。
