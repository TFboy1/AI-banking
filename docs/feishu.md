# 可选飞书私聊接入

作品面向个人；飞书开发平台将此类应用称为“自建应用”。这是一种接入方式，并不改变银行助手的个人产品定位。当前交付包含适配代码，真实使用仍需账号拥有创建/使用应用及发布权限。尚未准备这些权限时，保持 `FEISHU_ENABLED=false` 即可完整使用 Web。

## 1. 准备应用

在 [飞书开放平台](https://open.feishu.cn/app) 创建带机器人能力的应用，或使用已有应用。按平台页面完成权限申请及发布流程。

本项目只需要机器人私聊消息与卡片操作，不需要通讯录、文档、群聊、审批或金融服务权限。

- 开通“读取用户发给机器人的单聊消息”：`im:message.p2p_msg:readonly`。
- 开通“以应用身份发消息”：`im:message:send_as_bot`。
- 订阅事件：`im.message.receive_v1`。
- 订阅新版卡片回传交互：`card.action.trigger`。
- 事件和回调均选用长连接接收。保持本地桥接进程运行后保存订阅配置，并完成应用发布。

参考：[官方 Python SDK](https://github.com/larksuite/oapi-sdk-python)、[消息与卡片长连接示例](https://github.com/larksuite/oapi-sdk-python/blob/v2_main/samples/ws/sample.py)、[飞书当前接入教程](https://www.feishu.cn/content/article/7651905073454304222)。平台界面及账号审批能力以你的账号实际情况为准。

## 2. 填写服务端配置

在项目根目录 `.env` 中填写：

```dotenv
FEISHU_ENABLED=true
FEISHU_APP_ID=你的应用ID
FEISHU_APP_SECRET=你的应用密钥
FEISHU_BRIDGE_TOKEN=至少32字符的随机长字符串
BACKEND_URL=http://127.0.0.1:8000
```

桥接密钥是本项目后端与飞书连接进程之间的认证凭证，与应用密钥不同。可本地生成：

```powershell
uv run python -c "import secrets; print(secrets.token_urlsafe(32))"
```

## 3. 启动

先安装额外依赖，再分别启动后端和桥接：

```powershell
uv sync --extra feishu --frozen --link-mode hardlink

# 终端一；--no-sync 保留刚安装的可选依赖
uv run --no-sync uvicorn banking.main:app --host 127.0.0.1 --port 8000

# 终端二
uv run --no-sync python -m banking.feishu_bridge
```

桥接进程主动建立 WebSocket 长连接；应用不需要提供公网 Webhook 地址。卡片回调仅进行本地确认事务和任务入队，模型处理异步进行，避免在回调中等待大模型。

## 4. 绑定个人模拟账户

1. 打开本地 Web，进入右上角“连接设置”。
2. 点击“生成私聊绑定码”。
3. 在机器人私聊中发送 `绑定 生成的绑定码`。
4. 收到绑定成功提示后，发送自然语言需求。

绑定码 10 分钟有效，只能使用一次。各有数账号分别生成绑定码；后台按租户、用户及私聊标识路由到对应的独立数据库。一个飞书身份只能关联一个有数账号，一个有数账号保留一个飞书绑定。跨账号关联须先在原账号的应用设置解除关联。为同一有数账号重新绑定会替换原绑定；旧卡片、旧支付链接及尚未发出的旧消息失效。当前部署使用单个银行服务进程，跨用户绑定通过进程内锁串行处理；扩展多进程部署前需要共享的绑定唯一性事务。

飞书与 Web 共享聊天和模拟银行状态：可以在飞书发起、Web 确认；旧卡片重复确认不会再次执行。仅支持文本私聊，群消息不处理。

飞书初始使用默认会话，Web 切换会话不改变飞书焦点。主动通知卡片的“在此继续处理”会把后续飞书文字切换到该通知对应会话，便于结合日报或生日信息继续提问。删除该会话后自动回到可用默认会话。停止/收尾按钮始终绑定卡片里的具体任务与会话，不会停止其他会话。删除会话不会撤销已完成交易。

## 故障定位

- 飞书设置显示未启用：检查 `.env`、桥接密钥长度并重启后端。
- 订阅保存失败：先确保桥接进程正在运行，凭证有效。
- 收不到机器人消息：检查消息权限、事件/回调订阅、应用发布状态及可用范围。
- 出现“先绑定”提示：重新从 Web 生成绑定码，在当前机器人私聊发送。
- 操作已执行但卡片没有更新：在 Web 查看真实回执。消息发送最多重试三次；发送失败不会重做银行交易。
- 修改配置后先重启后端，再重启桥接。只有完成实际私聊与卡片确认后，才算完成真实飞书联调。
# 飞书专用交易确认页（2026-10-18）

资金类确认卡新增“前往验证并支付”按钮，打开 `/feishu-pay.html`，只展示当前交易的用途、金额、详情、付款账户及验证表单。已指定的付款账户预选；未指定时由用户选择。红色操作仍需要支付密码和模拟交易短信，银行卡添加、证券和理财等沿用后台原有规则。本页不新增定时执行入口，也不能通过额外参数改变交易对象、金额或执行时间。

首次在飞书内打开且没有可用的有数登录会话时，需要手机号短信登录。登录身份必须属于该交易的有数账户；链接本身不代替登录或支付验证。当前已支持各有数账号独立绑定飞书，支付链接按各自账户隔离。

配置 `FEISHU_PUBLIC_URL=https://你的有数站点域名`，该地址须提供同一有数后台及静态资源；将 HTTPS 代理到本机服务即可。它与桥接程序访问银行的 `BACKEND_URL` 分离。留空回退 `BACKEND_URL`，只适合本机浏览器验证，手机不能通过电脑的 `127.0.0.1` 访问。仅允许 HTTPS 根地址（本机回环地址允许 HTTP），不能填写第三方收集页面或带账号、查询参数的地址。原有应用凭证和长连接配置仍需完成，本变更不会自动开启飞书。

链接凭证采用桥接密钥派生的 HMAC-SHA256 签名，绑定审批、飞书绑定身份、银行身份安全状态、原参数、摘要与原审批到期时间（通常15分钟）。凭证放在 URL 片段中，页面载入后移入当前标签页的 sessionStorage 并清除地址栏片段；不放查询字符串，不加载第三方脚本。API 通过专用请求头校验凭证及已登录账号。绑定或密码、交易参数变化会使待支付链接失效。不要分享支付链接；手机短信当前仍为界面内模拟验证码。

支付调用现有 Agent 的确认入口：复用账户余额、风险等级、日累计门槛、报价时效、密码错误计数、短信与付款账户绑定、安全熔断、审计及幂等事务。成功后原飞书卡片进入发件队列更新回执。页面显示实际成功/取消/失败状态，提供关闭按钮和手动返回提示；是否允许脚本关闭取决于客户端。关闭页面不会取消成功交易；连接中断时只重新查询状态，不自动重发支付。重复点击或刷新不会重复扣款。链接到期后请回原飞书会话核对最终结果。

普通非资金确认仍保留卡片确认/取消按钮。新型复杂报告若未适配飞书原生布局，会发送摘要及回有数查看提示，避免卡片渲染失败。

测试：`backend/tests/test_feishu_payment.py` 覆盖登录、错账号、签名伪造、过期/解绑/改密/改参数、密码错误、红色短信及付款账户绑定、取消、重复提交、原卡片回执更新。本地隔离验证不代表真实飞书平台端到端联调完成。

## 飞书对话与通知补齐（2026-10-18）

- 输入“转人工”会转入现有管理员工作台。该人工服务的接入、客服回复、结束提示、半星评分同步回原飞书私聊；普通网页对话不自动转发。系统安全锁定后，已绑定用户仍可联系人工，但交易和恢复任务被拒绝，不能通过飞书解除系统锁定。
- 任务进度卡提供“停止任务”，处理中也可发送“停止”“暂停”“停止任务”等明确短语。中断取消正在等待的大模型任务，未完成资金操作失败；已落账交易保持不变，并返回实际扣款、到账和回执核对。失败/中断的任务卡提供“核对并继续”，复用已保存检查点，成功步骤不重做。
- 部分成功卡显示实际已完成事项和资金结果，提供“保留完成项目”“重选未完成项目”及符合条件的旅行整单退订。旧版本按钮被拒绝。退订只生成新确认卡，经专用支付页完成原有验证后退款，不由回调直接退钱；已成功转账或股票买卖不提供自动撤销。
- 日报、特别关心的生日提醒、定时交易执行结果进入持久化发件队列。应用设置的飞书区域可关闭主动推送或解除关联；关闭推送不影响正常对话及人工回复。仍遵循原日报时间/关闭设置、生日特别关心规则及定时授权规则。日报卡以文本显示截止时间和数据摘要，图表仍在有数网页。
- 每条待发消息固化收件人及绑定代次；解绑、换绑或同身份重新绑定都不会把旧消息发给新绑定。通知幂等依赖业务生成记录及消息编号；网络重试只重发消息，不重复执行业务。银行启动后为已注册账号恢复发送器，离线用户也能收到新通知；最多3次发送失败后保留失败记录，不无限重试。已发送或正在被平台接收的消息无法通过解绑撤回。
- 新增绑定、任务控制和半星评分回调都复用桥接鉴权、身份匹配及事件去重；跨账号/跨会话/旧绑定的任务按钮不能操作其他账户。

仍需真实配置飞书自建应用、长连接、消息和卡片权限及公开 HTTPS 支付地址。测试使用模拟飞书 API，不发送真实消息，不代表完成平台验收。本轮没有新增群聊、语音图片识别、图表图片渲染或后台代替用户完成交易验证。

### 接收回执超时提示修复

普通消息转发的连接等待为2秒、读取接收回执等待为15秒；卡片回调仍使用2秒预算。桥接访问本机后台不使用系统 HTTP 代理。连接尚未建立时提示连接问题；发送或读取超时、连接中断时仅提示“暂未取得接收回执”，不能推断后台未受理或交易失败。后台可能已经持久化事件并入队，后续应以任务卡片和执行回执为准。桥接不自动重发业务；平台重投继续使用同一事件编号，由银行去重。`test_feishu_bridge.py` 用延迟超过2秒的真实本机 HTTP 服务复现旧误报，并覆盖未知接收状态和卡片响应预算。
