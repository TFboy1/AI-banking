# 运行中断与资金核对

运行时发送按钮替换为实心方形“停止当前任务”。点击停止后，停止当前模型/工具处理与后续步骤，并生成确定性的中断报告。停止不撤销已经完成的交易，也没有自动恢复或补偿。

## 执行与安全边界

- 每个任务使用独立可取消协程，取消任务不会杀死处理其他任务的工作线程。排队任务也能取消，之后不会开始执行。
- 后台先在事务中把任务标为已停止（失败状态）、将未完成的确认交易标记失败、停止未完成DAG节点，再取消对应协程。模型或外部接口的晚到结果通过任务状态检查拦截，不能重新生成审批、继续变更或覆盖停止状态。
- 资金变更及回执写入仍在同一数据库事务内完成。停止请求与确认请求以事务处理顺序为准：确认先提交时保留交易；停止先处理时确认卡失效，不扣款。不在资金提交过程中强行终止数据库事务。
- 外部自动非资金变更已发出、但尚未收到结果时标为“结果待核查”，不把取消网络等待误当作远端撤销。

## 报告依据

中断报告直接读取本任务已执行审批的成功回执和对应交易流水，显示停止位置、已完成步骤、已扣款金额、已入账金额、回执编号与未执行步骤。

- 尚未执行资金操作：明确没有本任务的扣款和入账记录。
- 本人账户转账：核对转出与转入两条流水，分别显示扣款和到账，并保留实际余额变化。
- 外部收款人：展示已扣款与模拟转账成功回执；没有独立收款方到账记录时明确说明，不能编造外部到账核验。
- 理财、证券、外卖及其他变更：保留已经提交的业务回执和资金流水。
- 停止请求到达时任务已经结束：显示实际结束结果，不把完成交易改为未执行。
- 重复停止返回同一报告，不重复生成消息或交易。刷新恢复持久化报告和节点状态。界面通过HTTP返回报告立即显示，同时继续兼容SSE更新。

入口：已登录用户调用`POST /api/tasks/{task_id}/interrupt`，提交所属会话`conversation_id`。沿用用户数据库隔离与会话校验。报告保存在任务状态和会话消息中。

验证覆盖：模型处理中停止、排队取消、确认前停止、到账后停止、完成后停止、重复请求、晚到模型结果、外部非资金结果不确定、工作线程可继续处理新任务、认证与会话校验，以及页面按钮、刷新和窄屏展示。

修复：等待确认时保留方形停止按钮，密码窗口也有“停止交易”入口。证券买卖、外卖等业务流水按精确操作编号及冒号后缀统一核对，不使用易误匹配的通配符。买入显示实际扣款；卖出显示实际到账，买入不会虚构现金到账。

打开会话时会重新核对旧版中断报告的金额，并更新原报告；不新增交易、不重复扣款，不改变原停止时间和交易结果。
