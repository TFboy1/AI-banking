# 账户互转与对话添加银行卡

- 日常、储蓄、自定义分类账户支持相互转账；账户行新增“转账”，无需先绑定银行卡。原有银行卡与账户双向划转继续可用。投资账户仅为持仓汇总，不可直接划转。
- 页面或AI对话均通过`transfer_own_funds`创建确认卡；支付窗口选择付款账户，继续验证密码及红色操作短信。本人账户转账计入北京时间当日累计：累计不超过1000元为黄色，超过为红色。门槛固定。
- 后台执行时重新检查双方账户、余额及资金预留；同账户、投资账户、无效账户不允许转账。转出、转入双向记账，分类为“内部转账”，总余额不变，不计入日常收入支出。
- AI通过`add_bank_card`添加本人银行卡，银行名称和完整16至19位卡号须由用户提供。支持先提供卡号，再补充银行名称。不得用联系人添加代替本人绑卡。
- 确认卡只显示卡号尾号；AI和页面入口均先创建待确认操作，必须验证支付密码与短信验证码后才调用同一后台函数。新卡默认模拟余额5000元；重复添加拒绝；解绑后重新绑定保留原余额、冻结状态和限额，不重新增加资金。
- 每项变更进入DAG并以实际回执为准。处理步骤默认收起，切换到新任务和刷新后仍默认收起。
- 仍为演示数据，不连接银行查询真实银行卡余额，不执行真实转账。

验证包含隔离账户下的密码与短信边界、双向记账与总额、重复确认、取消、重复绑卡、卡号来源、多轮补充银行名、页面入口及默认收起状态。结构化模型输出中的裸`query`因联系人、股票、外卖检索共用字段而存在歧义，保持要求明确工具名称的现有安全行为，修正了两项旧兼容测试的预期。
